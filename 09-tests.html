11  The tests

A test is how you make a verification permanent. You will check a recode once by hand; you will not check it again in six weeks when somebody — you, a collaborator, an agent — “improves” it. testthat turns the check into something that fails on its own.

11.1 What testthat is

R’s unit-testing package. A test file is ordinary R code that asserts rather than prints: it states what must be true and fails loudly when it is not. Files live in tests/testthat/ and are named test-*.R.

test_that("what must be true", {
  expect_true(...)
})

The string is the failure message, so write it as a claim.

Expectation Asserts
expect_equal(x, y) equal within numerical tolerance
expect_identical(x, y) exactly identical
expect_true(x) all of x is TRUE
expect_setequal(x, y) same values, any order
expect_length(x, n) length is n
expect_error(f()) it does fail
expect_no_warning(f()) it runs clean
skip("reason") not applicable in this environment

11.2 Two kinds of test

The suite is split by what each test needs in order to run, because that is what determines how fast it is and how precisely it points at a failure.

Unit Integration
Files test-unit-*.R test-integration-*.R
What it tests one function the pieces working together
Input synthetic, written in the test the real CSV, the built .rds, the app
Fails when the function’s logic is wrong the wiring is wrong
Runs in milliseconds seconds

A unit test for bin_age() tells you the breaks moved. An integration test on data/wss_clean.rds tells you something upstream changed. You want both: the first is precise, the second is what actually catches the agent that edited the recode and broke the app.

Unit tests need units A 200-line script has nothing to unit-test. The reason R/functions.R exists — pure helpers taking data in and returning data out, no reading, no writing — is that it makes the recode’s logic testable without the survey file at all. Extracting the functions came first; the tests came second.

11.2.1 Unit: the recode helpers

#> # UNIT. Pure recode helpers, synthetic input, no survey file touched.
#> library(tidyverse)
#> source(repo_path("R/functions.R"))
#> 
#> test_that("auth_scale averages the four items onto 0-1", {
#>   items <- tibble(a = c(0, 1, 0.5), b = c(0, 1, 0.5), c = c(0, 1, 0), d = c(0, 1, 1))
#>   expect_equal(auth_scale(items), c(0, 1, 0.5))
#> })
#> 
#> test_that("auth_scale ignores partial missingness but keeps all-missing as NA", {
#>   items <- tibble(a = c(1, NA), b = c(NA, NA), c = c(1, NA), d = c(NA, NA))
#>   expect_equal(auth_scale(items), c(1, NA_real_))
#> })
#> 
#> test_that("auth_scale rejects anything that is not four items", {
#>   expect_error(auth_scale(tibble(a = 1, b = 0, c = 1)))
#> })
#> 
#> test_that("bin_auth cuts at .25 and .75, inclusive on the low side", {
#>   expect_equal(
#>     as.character(bin_auth(c(0, .25, .26, .75, .76, 1))),
#>     c("Low", "Low", "Middle", "Middle", "High", "High")
#>   )
#> })
#> 
#> test_that("bin_age uses the documented breaks and excludes under-18", {
#>   expect_equal(
#>     as.character(bin_age(c(18, 29, 30, 44, 45, 64, 65, 92))),
#>     c("18-29", "18-29", "30-44", "30-44", "45-64", "45-64", "65+", "65+")
#>   )
#>   expect_true(is.na(bin_age(17)))
#> })
#> 
#> test_that("pid_to_party3 follows the codebook's 1-7 scale", {
#>   expect_equal(
#>     pid_to_party3(1:7),
#>     c("Democrat", "Democrat", "Democrat", "Independent",
#>       "Republican", "Republican", "Republican")
#>   )
#>   expect_true(is.na(pid_to_party3(NA_real_)))
#> })

Every input here is written out in the test. Nothing on disk can make these pass or fail, so when one goes red the fault is in the function and nowhere else.

11.2.2 Unit: the estimator

#> # UNIT. trump_share() against a toy frame whose answer is known by hand.
#> library(tidyverse)
#> source(repo_path("R/functions.R"))
#> 
#> toy <- tibble(
#>   year       = factor(c(2020, 2020, 2020, 2024, 2024)),
#>   latino     = factor(c("Latino", "Latino", "Non-Latino", "Latino", "Latino")),
#>   trump_vote = c(1, 0, 1, 1, NA),
#>   weight     = c(3, 1, 1, 1, 1)
#> )
#> 
#> test_that("unweighted share is the plain mean of observed votes", {
#>   out <- trump_share(toy, "latino", weighted = FALSE) |> filter(year == "2020", latino == "Latino")
#>   expect_equal(out$trump, 0.5)
#> })
#> 
#> test_that("weights shift the share as specified", {
#>   out <- trump_share(toy, "latino", weighted = TRUE) |> filter(year == "2020", latino == "Latino")
#>   expect_equal(out$trump, 0.75)
#> })
#> 
#> test_that("n_obs and n_miss are reported and sum to the cell size", {
#>   out <- trump_share(toy, "latino") |> filter(year == "2024", latino == "Latino")
#>   expect_equal(out$n_obs, 1L)
#>   expect_equal(out$n_miss, 1L)
#> })
#> 
#> test_that("rows missing the grouping variable are dropped, not silently pooled", {
#>   with_na <- toy |> mutate(latino = factor(c(NA, "Latino", "Non-Latino", "Latino", "Latino")))
#>   expect_false(any(is.na(trump_share(with_na, "latino")$latino)))
#> })
#> 
#> test_that("an unknown grouping column fails loudly", {
#>   expect_error(trump_share(toy, "not_a_column"))
#> })

A five-row frame whose weighted mean you can do in your head is worth more than a thousand real rows whose answer you would have to trust.

11.2.3 Integration: the pipeline

#> # INTEGRATION. The artifact R/01_recode.R actually produced, from the real CSV.
#> library(tidyverse)
#> 
#> rds <- repo_path("data/wss_clean.rds")
#> if (!file.exists(rds)) skip("data/wss_clean.rds not built; run Rscript R/01_recode.R")
#> wss <- read_rds(rds)
#> 
#> test_that("the recode keeps every respondent", {
#>   expect_equal(nrow(wss), 7600)
#>   expect_setequal(levels(wss$year), c("2020", "2024"))
#> })
#> 
#> test_that("every derived variable the recode promises is present", {
#>   expect_true(all(c("authoritarianism", "auth_group", "age_group",
#>                     "party3", "race4", "latino") %in% names(wss)))
#> })
#> 
#> test_that("authoritarianism is a 0-1 mean of four items", {
#>   expect_true(all(wss$authoritarianism >= 0 & wss$authoritarianism <= 1, na.rm = TRUE))
#>   expect_setequal(levels(wss$auth_group), c("Low", "Middle", "High"))
#> })
#> 
#> test_that("trump_vote is coded only for two-party voters", {
#>   expect_setequal(unique(na.omit(wss$trump_vote)), c(0, 1))
#>   expect_equal(sum(!is.na(wss$trump_vote)), 6495)
#> })
#> 
#> test_that("latino and party3 take the documented values", {
#>   expect_setequal(levels(wss$latino), c("Non-Latino", "Latino"))
#>   expect_setequal(na.omit(unique(wss$party3)), c("Democrat", "Independent", "Republican"))
#> })
#> 
#> test_that("weights are positive where a vote is observed", {
#>   voters <- wss[!is.na(wss$trump_vote), ]
#>   expect_true(all(voters$weight > 0))
#>   expect_equal(sum(is.na(voters$weight)), 0)
#> })
#> 
#> test_that("the recode is reproducible from the CSV it documents", {
#>   csv <- repo_path("data/wss_2020_2024.csv")
#>   skip_if_not(file.exists(csv))
#>   raw <- read_csv(csv, show_col_types = FALSE)
#>   expect_equal(nrow(raw), nrow(wss))
#>   expect_true(all(c("auth1", "auth2", "auth3", "auth4", "pid7") %in% names(raw)))
#> })

Four properties worth asserting about any recode, all of them here: the row count is unchanged, derived scales are in range, categorical variables take only documented values, and the analysis N is what you think it is.

11.2.4 Integration: the app

#> # INTEGRATION. The Shiny server with the real data behind it: inputs in, table out.
#> library(shiny)
#> library(tidyverse)
#> 
#> app_dir <- repo_path("app")
#> if (!file.exists(repo_path("data/wss_clean.rds"))) {
#>   skip("data/wss_clean.rds not built; run Rscript R/01_recode.R")
#> }
#> 
#> test_that("the app reacts to its inputs and returns one row per year and group", {
#>   testServer(app_dir, {
#>     session$setInputs(state = c("AZ", "NM"), by = "latino", wt = TRUE)
#>     out <- est()
#>     expect_setequal(as.character(out$year), c("2020", "2024"))
#>     expect_setequal(as.character(out$latino), c("Latino", "Non-Latino"))
#>     expect_true(all(out$trump >= 0 & out$trump <= 1))
#>     expect_true(all(c("n_obs", "n_miss") %in% names(out)))
#>   })
#> })
#> 
#> test_that("the weights toggle changes the estimate it claims to change", {
#>   testServer(app_dir, {
#>     session$setInputs(state = c("AZ", "CO", "NV", "NM", "UT"), by = "latino", wt = TRUE)
#>     weighted <- est()$trump
#>     session$setInputs(wt = FALSE)
#>     expect_false(isTRUE(all.equal(weighted, est()$trump)))
#>   })
#> })
#> 
#> test_that("narrowing the state filter never grows the sample", {
#>   testServer(app_dir, {
#>     session$setInputs(state = c("AZ", "CO", "NV", "NM", "UT"), by = "auth_group", wt = TRUE)
#>     all_states <- sum(est()$n_obs)
#>     session$setInputs(state = "AZ")
#>     expect_lte(sum(est()$n_obs), all_states)
#>   })
#> })

shiny::testServer() runs the server function without a browser: set inputs, read the reactives. It caught a real bug while this chapter was being written — the server was declared function(input, output), and testServer() requires session as well.

11.4 What a failure looks like

Change a recode and the claim goes red. Here the assertion is deliberately wrong:

library(testthat)
wss <- readRDS("data/wss_clean.rds")

test_that("trump_vote is coded for every respondent", {
  expect_equal(sum(!is.na(wss$trump_vote)), nrow(wss))
})
#> ── Failure: trump_vote is coded for every respondent ───────────────────────────
#> Expected `sum(!is.na(wss$trump_vote))` to equal `nrow(wss)`.
#> Differences:
#> 1/1 mismatches
#> [1] 6495 - 7600 == -1105
#> Error:
#> ! Test failed with 1 failure and 0 successes.

That is the useful output: the claim, the expected value, the actual value. A silent recode error produces a number; a test produces this.

11.5 Tests worth adding

  • One per derived variable, asserting range and allowed values.
  • One asserting nrow() after the recode — the cheapest guard against a join that multiplied rows.
  • One asserting the analysis N, so a change in missingness cannot pass unnoticed.
  • expect_error() on the input guard: if someone hands the recode a file without auth1:auth4, it should fail rather than produce NaN.

A good use of an agent “Read R/01_recode.R and write a testthat test for every derived variable: range, allowed values, and row count. Do not change the recode.”

Then read the tests. They are far easier to check than the recode they protect, and reading them is how you find out whether the agent understood the codebook or guessed.
